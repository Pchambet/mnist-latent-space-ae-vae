A denoiser that loses to a median filter, and a VAE that ignores its latent space

A convolutional denoising autoencoder and a variational autoencoder from an earlier implementation, re-audited against the baselines any model should beat. The denoiser is limited by its 16-dimensional code: fixing its output head barely helps, a wider network does. The VAE is broken by a mis-scaled loss: the correct objective brings its latent space back. Every effect is measured on the MNIST test set.

The question

A denoiser is useful only if its output is closer to the clean image than its input is. A VAE latent is useful only if the model actually encodes information in it. Both checks are cheap, and neither was in the earlier implementation. Running them turns two figures that "look fine" into two measurable failures: one comes from the architecture, the other from a bug in the loss.

Setup

  • Data: MNIST, official 60k/10k split; the last 10k images of a seeded shuffle of the training set are held out for checkpoint selection. The test set is never used for selection.
  • Noise: additive U(−a/2, a/2) noise, clipped to [0, 1]. About 80% of MNIST pixels are exactly 0, so clipping removes half of the noise on them: at a = $ref_amp doing nothing already scores MSE $ident_mse.
  • Baselines: the noisy input itself and a 3×3 median filter, scored on the same corrupted test images as every model.
  • Models: the original 5-layer convolutional AE and VAE, with (a) the original output head, BatchNorm + LeakyReLU on the output image, and (b) a sigmoid head; a "blind" narrow AE ($params_narrow parameters, 16-d code) and a wider 4-layer AE ($params_wide parameters, 128-d code), both trained on fresh noise of random amplitude up to $max_amp; VAEs trained on the original loss and on the Bernoulli ELBO with β ∈ {1, 4, 16, 64}, plus a 2-D latent.
  • Protocol: $epochs epochs of Adam (lr 10⁻³, batch 128), best validation checkpoint, one seed, run on $device. The earlier implementation used 10k training images, batch 512, 20 epochs and, through a bug, the last epoch's weights; only its architecture, output head, noise and loss are reproduced here.

Failure 1: a 16-dimensional code, not the output head

Every decoder block of the original AE, the last one included, was ConvTranspose → BatchNorm → LeakyReLU, so the output image is normalised per batch and unbounded. That is a real bug, but a small one. Retrained under the protocol above, the original AE scores $orig_mse at a = $ref_amp, $orig_vs_identity ($orig_diff MSE, 95% CI $orig_ci over test images). With a sigmoid head the same network scores $head_mse ($head_gain), $head_vs_median the 3×3 median filter ($median_mse).

The limit is the bottleneck. On clean inputs, every AE with the original 16-d code has an error floor of $floor_16 MSE, against $ident_mse for the noisy input at a = $ref_amp. A wider 4-layer network with a 128-d code scores $wide_mse at a = $ref_amp, $wide_vs_median the median filter.

Failure 2: a KL term weighted 784 times too much

The original VAE loss averaged the squared error over the 784 pixels but summed the KL term over latent dimensions. Per image, the KL term is weighted 784 times more than the squared error (equivalently, a Gaussian decoder with a tiny fixed variance). The optimum is then to ignore the input: posterior collapse. Measured on the test set, the original loss leaves $leg_au of $latent_dim latent units active (KL $leg_kl nats per image); the ELBO (β = 1) keeps $fix_au of $latent_dim (KL $fix_kl nats). Limitations

  • One training seed on $device. Confidence intervals cover test-set sampling only, not training randomness; MPS is not bit-for-bit deterministic, so CPU or CUDA reruns match up to small numerical differences.
  • $epochs epochs per model, no tuning. The original AE was retrained under this protocol, not the earlier one (10k images, 20 epochs, last-epoch weights).
  • The narrow and wide AEs differ in depth and width as well as code size; the comparison is between two networks, not a clean bottleneck ablation.
  • The sample score depends on a 3-epoch judge CNN; it ranks models here and is not comparable with scores published elsewhere.
  • ELBO and IWAE values use a Bernoulli likelihood on grey-level pixels (see the note under the table).
